# Sidebar 与对话交互指南

**简体中文** | [English](../../en/guides/ui-guide.md) | [文档中心](../README.md)

默认从 Sidebar 打开；可选 Builtin 将同一组页面放入会话。v0.5 保留原有使用流程，增加主策略选择与三个记忆增强开关，不增加 View 页或通用插件管理器。全部配置位于**插件 → 可组合记忆**页面，DSH 0.1.7 把插件设置统一放在“插件”中。界面使用 DSH 的主题令牌与组件规格：按钮、开关、下拉选择、标签、状态点和弹窗与 DSH 自带页面一致，配置按 DSH 的偏好行组织。

## 交互心智

侧栏“记忆系统”与“插件”使用同一种 DSH 原生入口，统一继承皮肤、选中状态和折叠图标。选择“插件”、其他原生面板或“新建会话”会离开记忆工作台；“返回会话”和 Escape 会回到当前会话。重复点击“记忆系统”保留当前页面，从任务看板或 SSH 返回时也会恢复它。

使用 `displayMode: builtin` 时，从会话 Tab 打开“记忆系统”，Sidebar 不再显示入口。Host 使用所属会话的全局、工作区、集中工作区或自定义范围，因此顶部不显示存储范围和工作区选择器。以下 Source 页面与弹窗全部共用，对话快捷入口会打开匹配的 Tab。详见[范围映射](../reference/configuration.md#入口位置displaymode-与-tabenabled)。

Builtin 正在显示记忆系统时，仅隐藏所属会话的宽度拖动手柄。常驻输入框仍可使用；切回对话或其他视图后，宽度拖动会恢复。其他插件渲染的相邻或嵌套会话保留各自的行为。

一级页仍按**状态、运行时记忆、项目档案、记忆空间**排列：每个 Source 的页面使用其组件声明的名称，与配置页一致；已安装 Source 的页面以同样方式加入。记忆空间内部再分为**概览、检索、内容、实体**，右上角保留“沉淀记忆”和“沉淀策略”。生成的 View 是每轮内部运行时产物，不单独占用导航页面，状态页也不承担插件发现或安装。

四个页面使用相同的内容边距和单一页面滚动区域。滚动时主标题保持可见，记忆空间的标题、操作和内部 Tab 一起固定。切换一级页或记忆空间内部 Tab 时从顶部开始，不移动会话或其他插件面板。打开关联记忆时，标题与关闭按钮会显示在固定头部下方。档案阅读区、关联记忆阅读区与弹窗仍保留各自有界的滚动区域。

| 看到的动作 | 点击后发生什么 | 是否启动独立任务 Agent |
|---|---|---|
| 刷新状态、立即同步、点击记忆空间卡片重连 | Host 异步读取；当前区域右上角或卡片状态灯显示一个转圈 | 否 |
| 选择主策略或切换记忆增强 | 改变后续回合的记忆组合方式，或开启、关闭一个随附行为 | 否 |
| 直接检索、浏览内容、查看实体 | 并发调用 Provider 原生只读能力，结果到达即展示 | 否 |
| Agent 查询 | 先召回，再把有界证据交给无会话历史的顶层任务 Agent | 是，只读 |
| 沉淀记忆 / 存入记忆 | 先弹出可编辑确认，再判断价值、查重、提炼、选路与写入 | 确认后启动 |
| AI 维护元信息 | 每个记忆空间独立快速采样并异步生成，失败只留在对应卡片 | 是，每个记忆空间互相隔离 |
| 归档 | 先建立可检索冷引用，再由 Host 移动原文 | 确认后启动 |

## 1. 状态：先判断系统是否可用

![当前状态与 Native 就绪情况](../../assets/webui-v0.5.4/zh-CN/status.jpg)

最上方“记忆引擎”只展示 dsh-mnemon。“记忆 Provider”列表把 Mnemon Native 排在第一行（安装 CLI 或已有 Native 空间时显示），其余 Provider 逐项显示启用、健康和连接信息；局部异常只标在对应行，不会提升成整个系统故障。

页面采用渐进式并发加载；正在读取时只保留一个区域级转圈，已经返回的数据立即可见。“记忆引擎”之后，每个 Source 组件都有一张以其声明名称命名的卡片：显示它提供的内容（运行时记忆的条目、项目档案的活跃与归档文档、记忆空间的已激活空间），已安装但未提供内容的 Source 则显示正在运行。状态页还展示存储根（各存储区使用相同的名称）以及 dsh-mnemon / Mnemon 版本。页头以同样方式显示正在组合记忆的主策略。

记忆需要处理时，页面上方显示提示并提供**前往配置**：没有主策略运行时显示“记忆未生效”（对话照常进行，但不会使用记忆）；组件变更被拒、之前的组合仍在运行时显示“最近的组件变更没有生效”；由兜底策略组合时显示“所选主策略没有运行”。某一层被关闭、它的 Source 组件已停用或记忆未组合时，对应的状态卡片直接说明原因，而不是停在等待数据。

### 检查版本

![按 CLI 当前安装状态提供 npm 引导](../../assets/webui-v0.5.4/zh-CN/versions.jpg)

版本检查只读，不会自动安装。Mnemon CLI 区分未安装、版本不可读、已是最新和可更新，并提供可复制的 npm 安装、迁移或更新命令。远程检查失败时仍保留本地安装指引。命令应在 DSH 宿主终端执行；安装或修改 PATH 后，核对界面显示的可执行文件路径。

展开 dsh-mnemon 下的“子包版本”，按 Source、Strategy、Provider 查看已安装版本、已发布版本、主包指定版本和维护方式。默认依赖随主包升级到经过验证的组合；在当前 Profile 中独立安装的子包可单独更新；源码链接提供本地构建说明。页面更新需要管理权限且开启 `writeEnabled`，只读模式仍可检查版本和复制命令。更新插件包后重启 `dsh web`；后续重新检查仍保留待重启提示。

## 记忆增强：只呈现稳定行为

![默认记忆层与三个可选增强](../../assets/webui-v0.5.4/zh-CN/enhancements.jpg)

系统不提供独立的“视图”页面，也不在状态页暴露插件清单、依赖图或安装流程。记忆在**插件 → 可组合记忆**页面的**记忆组合**面板中组合，面板由已安装组件的声明生成；随附组件与已安装的扩展按同一种方式命名、关联和配置：

- **主策略**始终是一个选择器，无论安装了几个，每项都带说明。Starter 随附**分层策略**（运行时记忆常驻，档案与记忆空间按需读取，并保留此前版本的自动维护）与**通用策略**（全部可用 Source 共享一份预算，由模型自行决定如何使用，不做自动审查或容量维护）；
- 其他组件按各自声明的角色分组，并显示已开启的数量：**记忆来源**、**增强**，新的角色会自成一组。每行包含组件的名称与说明、与 DSH 组件列表一致的状态、有自己设置时的齿轮，以及开关；点击齿轮或名称都会打开它的页面。行内的关联标签点名相关组件：它需要的，或依赖它的，点击即打开对应组件的页面。为其他主策略编写的增强收在折叠分组中；
- 只有记忆没有按所选方式组合时，才出现一行问题提示，并给出唯一的修复开关：重新开启所选主策略、改用暂代它的主策略、关闭空转的另一个主策略，或在没有来源运行时开启一个来源；
- 组件较多时出现搜索，可按名称、说明或包名筛选。

每个开关立即应用于后续回合，已经固定视图的回合不被改写。开启组件会一同开启它需要的组件，并关闭不能与它同时运行的组件（声明了同一独占能力或同一增强槽位）；关闭组件会一同关闭依赖它的组件；选择主策略会关闭其他主策略，以及只有它们才能承载的组件。最后一个运行中的来源保持开启。所选主策略没有运行时，其他开关暂不可用，因为 Host 会按所选主策略校验每次修改。只影响自身一行的开关不再额外提示；影响了其他组件、切换了主策略或改变了组合方式的修改，会用 DSH 的提示条说明并提供**撤销**；在别处做出的修改（例如页面下方 DSH 的组件列表）提供**查看**；被拒绝的修改提供**重试**。

组件页可以从行内的齿轮、**主策略**旁的齿轮（打开当前主策略）打开，也可以点击组件名称打开：面板中的行、关联标签、存储的“用于”标签，以及另一个组件页中的名称；后者在原处打开，并可**返回**。组件页包含状态与开关、它是随附组件还是来自已安装的包、它需要什么、什么依赖它、什么不能与它同时运行、开关时还会带动哪些组件、它的选项，以及它自己提供的设置。选项由组件自己的字段声明生成（数字、文本、列表与来源选择），按 Host 相同的限制校验；改动后才出现**应用**，应用后页面保持打开。保持默认的选项不会写入，**恢复默认**可以把某项改回默认。第三方 Source/Strategy 通过 DSH 的插件列表安装，加载后出现在面板中；它们的声明与界面贡献如何决定呈现，见[记忆插件开发](../development/extensions.md)。

## 2. 运行时：维护每轮都需要的热记忆

![运行时总量与两条导入的用户画像](../../assets/webui-v0.5.4/zh-CN/runtime.jpg)

顶部汇总用户档案（`USER.md`）和工作记忆（`MEMORY.md`），下方用统一卡片展示具体条目。可以按来源、文本、分类和重要性筛选；再次点击已选筛选不会破坏页面。超长字段在自己的块内省略，悬停显示全文。

运行时条目显示创建时间，并按创建时间倒序排列；目标筛选、文本筛选与“再显示”均沿用此顺序。编辑旧条目不会把它移到顶部。

面向模型的 Runtime 快照也会显示每条投影记录的重要性，以及距创建和最后更新经过的完整天数。这些注释在每个新回合计算；存储正文和编辑器保持不变，当前指令仍然优先。参见[投影格式与限制](../reference/storage-model.md#事实源和投影)。

“编辑”和“移除”在对应目标内按条目的完整正文定位。短条目（例如 `X`）可以修改或移除，同时保留 `EGO_LINUX_CHROME`。同一目标内正文完全相同的多条记录仍有歧义，操作会被拒绝且不改动数据。

工作记忆达到容量上限时，Host 会归档完整原文。某个路由分块调用失败或返回无效方案时，该分块全部使用符合条件的默认记忆空间；没有默认空间时使用首个符合条件的空间。先前有效分块保留原有目标，维护摘要会记录回退原因。调用方取消仍会停止操作。

当前对话 View 创建的空间，或本回合中激活的已知空间，在激活且能力符合条件后可接收归档。回合开始后由其他操作创建的空间，需要新回合才能使用。目标失败会说明目录或范围限制，并保留已有 Runtime 条目；待新增内容尚未保存，应在修正原因后重试原始输入。

运行时条目应紧凑、独立、反复有用。身份、偏好和协作要求放用户档案；项目事实、环境、决策和工具经验放工作记忆。临时进度和原始日志不适合这一层。

工作记忆条目可带可选的分支范围（新增和编辑表单里用逗号分隔的 git 分支名）：带范围的条目显示分支徽标，只在会话 workspace 处于所列分支上时投影进模型上下文；留空则该条目在所有分支可见。分支范围不影响本页展示，也不影响磁盘上的 `USER.md`/`MEMORY.md` 投影。

Agent 通过 `mnemon_runtime_memory` 操作用户档案（`target=user`）时，可以省略 `branches` 或传入 `[]`；用户档案仍不接受非空分支范围。替换工作记忆时，`branches: []` 会清空条目的分支范围，省略该字段则保留原范围。

## 3. 档案：保留完整项目叙事

![导入的项目档案目录与 Markdown 阅读器](../../assets/webui-v0.5.4/zh-CN/documents.jpg)

先选择 DSH 工作区：全局或自定义存储下，Documents 也需要工作区身份。选中的会话提供所属工作区；工作区存储还允许显式选择查看对象。这用于确定项目，不会改变已选存储根。

左侧活跃/归档目录可切换；选中条目后重复点击仍保持选中，不会关闭右侧阅读器。右侧保留标题、检索说明、来源、revision、哈希、文件大小与完整 Markdown，切换档案时自动回到顶部。

活跃目录、归档目录和搜索匹配列表均显示创建日期，并在“再显示”分页前按创建时间倒序排列。更新旧档案不会把它移到顶部。

显式归档或前台容量维护时，独立任务 Agent 只拟定摘要并选择一个已有的合规记忆空间，不持有记忆工具。Host 先校验方案，补齐精确冷路径与内容哈希，写入索引并根据自己的回执生成 lineage，随后才移动原文。目标必须已启用，且支持精确写入和安全删除；归档前需配置合适的空间。

无效方案不会改变 active 文档或记忆空间。移动原文失败时，Host 尝试只清理本次新建的索引；已验证的已有索引会被复用，不会被清理删除。清理失败或 Provider 结果不确定时，应按错误中的目标空间和索引检查状态后再重试；这是补偿清理，不是跨 Provider 的数据库事务。

后台审查保留已有档案原文：先搜索，内容已覆盖时跳过，只有存在实质新增知识时才创建独立补充档案。后台不能更新或归档已有档案，容量不足时跳过创建。正常的显式编辑继续可用。

审查会复用已从完整对话继承的概览、文件片段、规则和工具结果，不能重新打开文件或调用其他插件的概览工具。证据缺失时可以进行有界的档案搜索；仍不足以判断时跳过该候选。

标题与检索说明决定未来是否容易找到，来源路径用于追溯，正文保留 Markdown 结构。项目源文件始终只读；工作台创建受管副本。

## 4. 记忆空间：统一管理可替换的第三层

### 概览与实时快照

![四个导入的记忆空间，其中两个已激活](../../assets/webui-v0.5.4/zh-CN/spaces.jpg)

实时快照从上到下分两层阅读：

- **快照可观察范围**中的每张卡片都对应一个已激活记忆空间，并先声明 Provider 真正提供的读取表面、投影方式与可观察数量。`真实关系图`、`内容投影`、`仅查询`是能力边界，不是质量等级；
- **多记忆空间实时快照**把这些可读取结果合并到同一张关系图。边的颜色表示空间归属、时间、语义、因果或实体关联，Provider 与记忆空间标签则保留来源；
- 图谱左下角汇总空间、记忆和实体总数，右下角显示当前渲染的元素与连接。类似 `60 / 129` 表示为保持交互流畅而展示的视窗，不表示其余数据丢失；
- 点击记忆空间、实体或记忆节点后，右侧检查器展示该元素的精确上下文。自然铺开、拖拽和均匀重置只改变布局，不改写 Provider 数据。

![两个已激活原生空间的实时图谱](../../assets/webui-v0.5.4/zh-CN/graph.jpg)

每张卡片对应一个真实记忆空间。Provider 标签只用颜色区分，不在标签内重复放图标；`Mnemon Native` 在目录统一展示为 `mnemon`。卡片点击区域用于按需重连当前 Provider + ID，状态灯在重连期间原位变成同尺寸转圈，不触发全量同步。

首次进入概览执行一次全量同步；之后只按需同步。右上角保留“立即同步”，旁边显示距离上次全量同步的时间。

“快照可观察范围”先说明每个记忆空间真实支持的读取表面，再生成多记忆空间实时快照：

- Mnemon Native 提供完整类型关系；
- Hindsight 与 Holographic 贡献各自的真实图谱；
- 没有边的 Provider 只贡献内容投影；
- ByteRover 等查询型 Provider 等待明确查询。

页面不会伪造 Provider 不具备的关系、实体、删除或浏览能力。

### 手动创建记忆空间

![为记忆空间填写名称并选择 Provider](../../assets/webui-v0.5.4/zh-CN/space-create.jpg)

手动点击“创建记忆空间”时始终由用户明确选择 Provider。只列出在**插件 → 可组合记忆**页面中已经启用的服务；Provider 特有字段按分行结构展示，避免横向对齐误差。创建完成后，该实例才进入目录、激活和检索工作流。

### 沉淀策略：人工指定或智能选择

沉淀策略影响后续 Agent 写入目标，不改变“创建记忆空间”这个人工动作：

- **人工指定**：由高级选项或现有范围明确目标。尚未保存目标时使用第一个已就绪的 Provider：安装 CLI 时为 Mnemon Native，否则为其他已启用的 Provider；
- **智能选择**：数据边界和能力要求是硬规则，本地/共享倾向和 Prompt 是软策略；只有多个候选都合格时才调用任务 Agent。

回执保留决定来源、置信度和理由，Provider 凭据不会进入模型上下文。

### AI 维护元信息

可多选已激活记忆空间。每个任务先调用对应 Provider 最快的原生查询方式读取少量样本，再按 system prompt 的长度和能力约束生成 title / description。任务互不共享状态；一个失败只在自己的卡片显示错误。如果模型生成的标题或说明未通过本地长度校验，该卡片会保留原有元数据，同时其他合法结果仍会更新。生成过程不关闭弹窗，卡片向右播放同色调刷新动画并原位更新。

人工生成的标题与说明属于本地目录元数据，普通重连不会覆盖；关闭 Provider 会清理映射和元数据，重新启用后从 Provider 重建，映射不到的字段用最近似默认值补充。

### 沉淀记忆

默认只需填写候选内容。点击确认后，独立任务 Agent 判断是否值得保存、选择最窄记忆空间、查重、提炼并写入。“人工高级选项”只用于确实需要约束目标记忆空间、分类或重要性时。

### 检索与 Agent 查询

![通过关键词检索导入的记录](../../assets/webui-v0.5.4/zh-CN/recall.jpg)

- **直接检索**返回原始证据，不启动 Agent；
- **Agent 查询**使用相同证据，再启动 evidence-only 顶层任务 Agent 组织答案；
- 各 Provider 并发返回，单个连接失败不隐藏其他来源；
- 跨 Provider 排序使用排名融合，同时保留原始分数、ID、记忆空间、Provider 与分类；
- 只有 Provider 真正支持时才显示关联、链接、浏览和遗忘动作。

具体问题通常比宽泛关键词更可靠。

### 内容与实体

![保留来源的 Native 证据](../../assets/webui-v0.5.4/zh-CN/content.jpg)

内容页区分可枚举、仅查询和不可浏览；Provider 标签既可点击筛选，也可再次点击取消。实体页只聚合真实实体索引，目前包括 Mnemon Native、Hindsight 与 Holographic；普通文本不会被伪装成实体能力。

[实体页](../../assets/webui-v0.5.4/zh-CN/entities.jpg)通过原生 APPSO 实体索引展示同一批导入证据的关联。

## 5. 配置：服务配置与记忆空间实例分开

DSH 0.1.7 在“插件”中每个插件自己的页面编辑其配置，“设置”只保留 DSH 自身的分组与只读的插件清单。打开**插件 → 可组合记忆**，或在“插件”页可用时点击记忆系统顶部的**配置**（齿轮）。页面依次是插件的标题与说明、配置，以及 Starter 包含的组件，各组件使用其声明的名称与说明。点击该列表中的组件名称会打开 DSH 为它提供的页面，其中是与面板相同的组件页：状态与开关、关系、选项以及组件自己的设置，关联组件在其上以弹窗打开。页首的**打开记忆系统**可回到工作台。

配置采用 DSH 的偏好行：左侧是名称与说明，右侧是下拉选择、开关或按钮。这里只放不属于任何组件的设置，各组件自己的设置在它的页面中：

| 位置 | 包含 | 生效方式 |
|---|---|---|
| 记忆组合 | 主策略、每个记忆来源与每个增强的开关 | 立即应用于后续回合 |
| 存储 | 存储范围、数据目录、备份与迁移 | 范围与目录点击其**应用**后生效；导入、导出 ZIP 立即执行 |
| 界面 | 记忆系统入口（侧边栏 / 会话标签页）、回合记忆栏、存入记忆按钮 | 立即生效 |
| “运行时记忆”页面 | 用户画像范围 | 立即生效 |
| “记忆空间”页面 | 记忆 Provider 与 Mnemon Native 嵌入 | 开关立即生效；需要输入的连接信息点击其**应用**或服务配置按钮 |
| “分层策略”页面 | 任务 Agent 模型、空闲审查 | 选择立即生效；审查参数点击其**应用** |

开关与下拉选择改动即生效，写入失败时恢复为已保存的值并就地说明原因；需要输入的值按组点击**应用**，改动后才出现。在其他窗口保存或直接修改 profile 后，页面无需刷新即显示新值。健康监控放在状态页，记忆空间发现放在概览，配置页不等待完整发现或检索。

- **存储**标题下列出数据保存在这里的组件，点击可打开它们的页面。
- **存储范围**可选“全局”“工作区”或“集中存储 · 按工作区隔离”。其应用行说明后果：应用后读写新位置，已有数据不会迁移、合并或删除。
- **数据目录**选择“默认”或“自定义”，并只显示记忆正在使用的一个目录。“默认”即 `MNEMON_DATA_DIR` 或 `~/.mnemon`，显示在标题下方；选择“集中存储 · 按工作区隔离”时，标题下方改为显示本工作区在默认根目录下的目录。“自定义”显示输入框，填写绝对路径或以 `~/` 开头的路径：选择“全局”时即改用该目录（配置中的 `custom` 范围，本质上是显式路径的全局范围）；选择集中存储时为集中根目录，各工作区的数据位于 `workspaces/<工作区路径哈希>/`。输入框留空不代表默认，而是等待填写；回到默认目录请选择“默认”。选择“工作区”时不需要目录，只显示该工作区的 `.mnemon`。
- **用户画像范围**在“运行时记忆”页面，可独立选择：“全局共享”会组合全局 USER.md 与工作区/自定义 MEMORY.md，不移动任何事实源。
- **备份与迁移**导出或导入当前数据目录的 ZIP，包含“存储”列出的组件（运行时记忆、项目档案和 Mnemon Native 记忆空间）的数据，不含第三方 Provider 数据和密钥。
- 记忆层与为它服务的 Source 组件共用一个开关；“开启”表示允许系统按需使用，并不表示每回合强制 Recall。此前配置中关闭的层也通过同一个开关重新开启。无法读取组件时，面板仍列出已保存的记忆层并可开关。
- 记忆 Provider 在“记忆空间”页面，“记忆空间”开启时才读取；否则页面提示用它自己的开关开启，与“记忆组合”中该行是同一个开关。dsh-mnemon 为只读（`writeEnabled: false`）时，Provider 开关停用并注明原因。
- Provider 卡片与 DSH 模型设置的卡片一致。Mnemon Native 排在第一张，展开后只包含它自己需要的本地向量嵌入设置；每个第三方 Provider 有独立开关，默认关闭，打开后才展开 endpoint、API Key 和 Provider 特有字段。
- 卡片上的“全局 / 工作区”标签显示当前有效范围；支持相同范围语义的 Provider 复用 Mnemon 的配置框架。
- OpenViking 可选的 **User Key 所属用户（跳过 Admin）** 字段用于没有 Admin API 权限的 key，显式选择一个用户空间，同时需要填写账号和 user key。数据面校验被拒时保留原服务配置。[配置与限制](./memory-providers.md#运维边界)；
- API Key 使用经典 password 输入，眼睛按钮在显示/隐藏之间切换；不再使用“清除凭证”checkbox、“移除”独占行或“已安全保存”提示。

### Mnemon Native 嵌入桥接

在“记忆空间”页面展开 Mnemon Native 卡片。“由 DSH 管理嵌入配置”开关立即生效，开启后保存的 Endpoint、模型、协议与可选 API Key 会成为 Mnemon 子进程的权威值，也适用于无法继承 shell 启动文件的 Desktop；这些字段在开关开启时显示，点击其**应用**一起保存。自动协议将以 `/v1` 结尾的 Endpoint 识别为 OpenAI 兼容；其他兼容地址需要显式选择协议。URL 拒绝内嵌凭据、查询参数与片段；记忆与查询正文会发送到所配置的服务。“测试状态”只检查已保存值，不把未保存草稿误报为生效。启用前请阅读[嵌入配置与安全边界](../reference/configuration.md)。

关闭记忆层不删除数据。Sidebar 中对应 Tab 保留并标记“已关闭”，点击后显示可逆停用说明而不读取数据面；重新开启后原数据恢复可用。Source 组件已停用的层保留原位置的 Tab 并标记“未运行”；没有主策略运行时，各层标记“未生效”。对应页面说明原因并提供前往配置，Source 恢复运行后自动回到该层自己的页面。已关闭的层也不接受 Source 管理与辅助操作。扩展贡献的新 Source 首次出现时默认关闭；保存前当前运行代继续服务，候选配置验证失败也不会产生半切换。

### 任务 Agent 模型

“分层策略”页面“后台任务”中的“任务 Agent 模型”选择“跟随主链路”时使用 DSH 新建 session 的默认模型；选择“指定模型”会立即以 DSH 的默认路由保存，并显示模型 Provider 与模型两个选择器，每次选择立即生效，切换 Provider 时从它的第一个模型开始，同名的 Provider 附上 id 区分。路由始终是完整的 Provider + Model。这个设置只影响 AI 元信息、Agent 查询、沉淀记忆、智能 Provider 选择和档案归档，不改变当前主会话模型。推理强度由所选模型 Provider 能力与 DSH 路由支持共同决定。

选择器展示 DSH 报告的模型能力。**图片输入**标记说明所选模型的能力；当前 Mnemon 后台任务仍只发送文本 Prompt。

开关、下拉选项与眼睛按钮都允许重复点击；即使选择当前已选值，也不会让配置页卸载或白屏。

## 6. 对话内交互

### 本回合记忆

只有已经完成且发生记忆活动的回合才显示。“本回合记忆”可以重复展开/收起；展开后列出具体工具，点击工具名跳转到对应检索、内容、实体或档案页面。

### 存入记忆

“存入记忆”位于已定稿回复的原生操作区。首次点击只读取这条回复并打开可编辑弹窗；取消不会产生任何写入。只有“确认并交给独立任务 Agent”才开始沉淀流程。

两项默认开启，可在**插件 → 可组合记忆**页面的“界面”组分别关闭，保存后即时生效。

Builtin 模式下，自动快捷跳转要求主对话中只有一个可明确识别的“记忆系统”标签。若分栏暴露多个可用对话标签，快捷跳转会保持待处理；请手动打开目标对话中的“记忆系统”。每个 Builtin 视图始终使用其所属会话。

## 工作区模式：查看与执行分离

| 概念 | 由什么决定 | 影响什么 |
|---|---|---|
| **查看工作区** | 工作台顶部选择器 | 当前页面展示与人工维护哪套 `<workspace>/.mnemon` |
| **执行工作区** | 当前对话 / Agent 的 cwd | 对话工具、命令与生命周期使用哪套目录 |

可以留在项目 A 对话中查看项目 B：对话 Agent 仍使用 A；从工作台发起的 AI 元信息、Agent 查询、沉淀和档案归档会启动独立任务 Agent，并显式使用查看工作区 B。没有选中主 session 时也可以正确执行。

远程 Provider 的 workspace、user、bank、project、container 和 URI 是独立命名空间，不会跟随 DSH 工作区被隐式改写。`global` 与 `custom` 只有一个明确根，不需要查看/执行对齐。

## 主题与皮肤覆盖

皮肤作者可从[皮肤开发与 Mnemon 适配](../development/skin-integration.md)开始，查看 dsh-web 接入示例、旧类名迁移和真实 WebUI 验证流程。本节定义受支持的表面约定。

Sidebar 与 Builtin 提供同一个受支持的工作台根选择器：`[data-dsh-plugin="dsh-mnemon"][data-dsh-part="mnemon-view"]`。主题作者可直接在该元素上设置下列受支持的自定义属性；只在祖先元素上赋值会被工作台自身的默认值覆盖。构建生成的 CSS-module 类名不属于公开选择器。

| 属性 | 接受的值与用途 | 默认值 |
|---|---|---|
| `--mn-bg` | 基础表面的 CSS 颜色 | `var(--dsw-alias-bg-base)` |
| `--mn-backdrop` | 默认叠层表面中，基础颜色背后的 CSS 颜色 | `var(--dsw-alias-bg-overlay, var(--mn-bg))` |
| `--mn-surface` | 工作台、页眉和画布使用的 CSS `background` 值 | 基础颜色渐变叠加在背衬渐变之上，并以基础颜色托底 |

默认表面仍为 `linear-gradient(var(--mn-bg), var(--mn-bg)), linear-gradient(var(--mn-backdrop), var(--mn-backdrop)) var(--mn-bg)`。皮肤把宿主基础颜色改为透明时，叠层背衬仍保障可读性；官方主题保持不透明。皮肤可以显式替换这套合成，例如：

```css
[data-dsh-plugin="dsh-mnemon"][data-dsh-part="mnemon-view"] {
  --mn-bg: rgb(232 241 249 / 74%);
  --mn-backdrop: var(--mn-bg);
  --mn-surface: var(--mn-bg);
}
```

请像示例一样，在未分层的样式表中使用这两个属性组成的选择器。其优先级 `(0,2,0)` 高于默认自定义属性声明的 `(0,1,0)`，因此无论皮肤样式表在 Mnemon 之前还是之后加载，都能覆盖默认值。单独的 `[data-dsh-part="mnemon-view"]` 与默认值优先级相同，会依赖样式表顺序；`@layer` 内的普通声明低于未分层的默认声明。如需限制皮肤生效范围，可在前面加上皮肤自己的祖先选择器。

这些属性会被使用它们的工作台后代元素继承。通过 portal 挂载到 `body` 的弹窗，以及其他插件的根元素，不在此选择器的范围内。替换 `--mn-surface` 后，表面的可读性与透明度由皮肤决定；不会改变设置、记忆数据或 Provider 行为。

## 常见规则

- 主动作使用 DSH 主按钮（浅色主题为黑底，深色主题为白底）；编辑等次要动作使用描边按钮；红色文字只用于删除、断开、归档或遗忘；查看、复制和取消使用中性按钮。
- 记忆空间开关只决定它是否参与 dsh-mnemon 读取路由，不等于 Mnemon CLI 默认 Store。
- Mnemon Native 物理删除需要二次确认；三方记忆空间使用“断开”，不删除 Provider 数据。
- 页面按区域异步加载；局部错误不阻塞其他区域，也不会堆叠多个转圈。
- 工作台默认从 Sidebar 打开，Builtin 将同一界面放入所属会话；本回合记忆和存入记忆仍作为对话内快捷入口。

## 空闲审查控制

“分层策略”页面“后台任务”中的**空闲审查**：开关、审查方式（有界 spawn 或完整上下文 fork；选择 fork 时还可指定上下文不可用时的处理方式）与 Agent Teams 兼容模式均立即生效；“审查参数”中的间隔（秒）、次数、检查点大小和输出预算点击其**应用**后生效。空闲审查只在“分层策略”组合记忆的回合之后运行。变更遵循现有 Host 设置授权；只读客户端不能保存。Agent Teams 兼容模式默认**暂停审查**，即 Agent Teams 运行时跳过审查；使用 DSH 与官方 Teams 0.1.7-rc.2 时，可选择**受限子代理审查**，在保留强制工具限制的前提下同时启用两项功能。记忆系统会显示配置中的 Team 暂停或失败后的部分写入回执，刷新状态即可读取当前状态。历史保留与重启限制见[配置说明](../reference/configuration.md)。
